## Long-Running Project Work

The canonical operating records are `docs/agent/PROJECT-PROFILE.md`,
`docs/agent/BATON-PROTOCOL.md`, and `docs/agent/CURRENT-BATON.md`. Read them before
substantive project work, then read relevant architecture, accepted decisions,
task files, and tests. Follow this repository's contract precedence.

Inspect Git and preserve human edits and unknown changes. Claim a bounded objective
through the documented coordination channel. Do not edit another contributor's
exclusive scope or overwrite an existing baton.

The coordinator alone maintains the shared current baton. Contributors use scoped
work records. Agents from different people inherit only their sponsor's recorded
authority, not blanket rights over other repos, environments, or releases.

Before a gated action, check `docs/agent/AUTHORIZATIONS.md`. Ask for new dependency,
protected-contract, release, deployment, costly retry, or destructive permissions
where the profile requires them. Do not ask again for unchanged covered approvals.

Build the requested usable flow and test the affected risks. Report exact checks,
gaps, release state, and one next action. A mock result is not live acceptance.
Respect human pause and checkpoint boundaries. Archive completed/deferred work with
its true outcome, then update current state without erasing unfinished criteria.

Keep instructions tool-neutral. Tool-specific wrappers point here rather than
copying policy. If a tool does not discover skills, read the protocol directly.
